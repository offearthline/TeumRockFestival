# 틈락페 🎸

틈 날때마다 즐기는 락페스티벌. 언제 들어와도 공연 중이고, 여러 사람이 같은 들판에 모여요.

## 실행

```bash
npm install
npm start
```

브라우저에서 http://localhost:3000 을 열어요. 같은 와이파이의 다른 기기에서는 `http://<내 컴퓨터 IP>:3000`으로 들어올 수 있어요.

화면엔 이름표가 없어요. 내 캐릭터 머리 위에만 노란 ▼ 화살표가 떠요.

## 처음 들어오면 (온보딩)

1. **이름**: 팔찌에 새길 이름을 적어요 (최대 12자)
2. **팔찌**: 진짜 락페처럼 그날의 입장 팔찌(1DAY PASS, 번호·날짜·바코드·색)를 채워줘요
3. **캐릭터**: 머리·옷·돗자리·깃발을 고르고 입장해요

팔찌는 하루짜리예요. 같은 날엔 새로고침해도 온보딩 없이 바로 같은 사람으로 들어가요. 한국 날짜가 바뀐 뒤 다시 오면 이름·캐릭터는 그대로 두고 **오늘의 입장 팔찌**(새 번호·새 색)만 새로 차고 들어가며, 며칠째 방문인지 알려줘요. 다시 들어오면 마지막에 있던 자리와 펴 둔 돗자리(그 자리가 비어 있으면)도 그대로예요. 처음부터 다시 해보려면 주소 뒤에 `?new`를 붙여요.

### 모바일 웹

폰 브라우저로 같은 주소에 들어오면 터치 조작으로 자동 전환돼요.

- 가고 싶은 곳을 터치하면 그쪽으로 걸어가요. 누른 채로 끌면 손가락을 따라와요 (텐트·무대처럼 못 가는 곳이면 앞에서 멈춰요)
- 아래 한 줄 버튼: ✋ 손들기 · 🎵 리듬 · 💥 슬램 · 🚩 깃발 · 🧺 돗자리 · 👕 꾸미기 (누르면 무엇이 켜졌는지 잠깐 알려줘요)
- 오른쪽 위 −/+ 버튼으로 줌을 바꿔요
- 세로·가로 화면 모두 지원해요

## 전광판 / 광고 바꾸기

[public/billboard.json](public/billboard.json)만 고치면 돼요. 서버를 재시작하지 않아도 1분 안에 모든 접속자 화면에 반영돼요.

- `festivalName`, `tagline`: HUD·팔찌·입장 화면에 나오는 이름과 한 줄 소개
- `stageName`: 메인 무대 현수막에 들어가는 영어 이름 (지금은 `TEUM ROCK FEST`)
- `lineup`, `setMinutes`: 무대에 오르는 밴드 순서와 한 팀당 공연 시간(분)
- `slides`: 왼쪽 전광판에 `slideSeconds`초씩 돌아가며 나오는 화면
  - `{"type":"text","icon":"📣","label":"AD SPACE","title":"...","sub":"...","bg":"#색","bg2":"#색","fg":"#색","accent":"#색"}`
    - `icon`(이모지)은 제목 위에, `label`은 작은 깜빡이는 글씨로, `sub`는 리본 모양으로 나와요 (모두 생략 가능)
    - `title`에 `\n`을 넣으면 줄바꿈돼요
    - 배경은 `bg`(위)에서 `bg2`(아래)로 그라데이션, `accent`는 글자 그림자·리본·장식 색이에요
  - `{"type":"insta","handle":"product.pt","sub":"Instagram"}`: 인스타그램 아이콘과 계정
  - `{"type":"nowplaying"}`: 지금 공연 중인 밴드
  - `{"type":"image","src":"ads/banner.png"}`: 광고 이미지. `public/ads/` 폴더에 넣고 경로를 적어요 (가로:세로 약 5:4)

### 하단 펜스 광고판

맵 맨 아래 펜스에 광고판 4칸이 걸려 있어요. `billboard.json`의 `fence`에 왼쪽부터 순서대로 적어요.

- `{"text":"광고 문의 환영","bg":"#5a1020","fg":"#ffe066","accent":"#ff5f5f"}`: 글자 광고. `accent`는 위아래 테두리 색이에요
- `{"src":"ads/fence1.png"}`: 이미지 광고. `public/ads/` 폴더에 넣어요 (가로:세로 약 13:1, 예: 520×40)
- 4개보다 적으면 빈칸에 "광고 문의 환영"이 나오고, 4개보다 많으면 `fenceSeconds`초(기본 10)마다 다음 4개로 넘어가요
- 밤에는 주변처럼 어두워져요

슬램 러시 중에는 왼쪽 전광판이 **💥 SLAM TIME · 에바뛰** 화면으로 바뀌고 박자마다 흔들려요. `billboard.json`에 `"slamSlide": {"title": "..."}`처럼 적으면 문구·색을 바꿀 수 있고, `"slamSlide": false`면 꺼져요.

주소 뒤에 `?slide=2`처럼 붙이면 그 번호(0부터 시작)의 화면에 고정돼서 미리보기하기 편해요.

오른쪽 전광판은 무대 위 멤버를 비추는 라이브캠이에요.

## 음악 넣기 (지금은 꺼져 있음)

재생 기능은 만들어 두었고 꺼져 있어요. 상업적으로 써도 되는 곡이 생기면:

1. 음원(mp3·m4a·wav·ogg)을 `public/music/` 폴더에 넣어요 (파일 이름은 상관없어요)
2. `billboard.json`에 아래 항목을 추가해요

```json
"music": { "src": "music/current", "title": "곡 제목", "artist": "아티스트", "credit": "", "bpm": 120, "offset": 0 }
```

- 모두가 서버 시각에 맞춰 같은 소절을 들어요 (곡이 끝나면 반복)
- 무대에 가까울수록 크게 들리고, 🔊 버튼이나 `M` 키로 끌 수 있어요
- `bpm`과 `offset`(첫 박자 위치, 초)을 맞추면 무대, 리듬타기, 조명이 박자에 맞춰 움직여요
- Suno 곡은 **유료 플랜으로 만든 곡만** 상업적으로 쓸 수 있어요. 광고를 붙일 계획이면 무료 플랜 곡은 넣지 마세요

## 정원과 웨이팅

한 번에 **200명**까지 들어올 수 있어요. 들판에 있는 NPC 관객(처음 137명)도 접속자 수와 정원에 같이 세요. 실제 사용자가 4명 이상이면 5분마다 NPC 3~8명이 옆 출구로 걸어 나가고(최소 40명까지), 그 사이사이 한 명씩 나갔다 들어왔다 해요. 사용자가 4명보다 적으면 5분마다 다시 돌아와요. 돗자리 위 NPC가 모두 나가면 그 돗자리도 걷혀서 그 자리를 쓸 수 있어요. NPC가 나가서 생긴 자리는 기다리던 사람이 먼저 들어가요.

누군가 **2분 넘게** 머물면 돗자리에 앉아 있던 NPC 20명이 일어나 스탠딩존 슬램에 합류해요(같이 슬램하면 부딪혀요). 2분 슬램하고(이때 전광판에 '에바뛰') 돗자리에서 5분 쉬었다가 다시 들어가기를 반복하고, 그런 사람이 모두 나가면 자기 돗자리로 돌아가요. 빨리 보려면 `RUSH_AFTER_SEC=8 RUSH_SLAM_SEC=8 RUSH_REST_SEC=8 npm start`. 꽉 차면 "지금 페스티벌이 꽉 찼어요. 밖에서 락페를 즐겨주세요" 카드와 함께 **웨이팅 번호**와 내 앞 사람 수가 나오고, 그동안 카메라가 무대와 들판을 천천히 둘러봐요. 누가 나가면 순서대로 자동 입장해요.

정원은 서버를 켤 때 바꿀 수 있어요 (테스트할 땐 작게):

```bash
CAPACITY=2 npm start
```

NPC가 드나드는 걸 빨리 보고 싶으면 `NPC_WAVE_SEC=10 npm start`처럼 5분 간격을 줄여요 (`NPC_MIN`으로 최소 인원도 바꿀 수 있어요).

부하 테스트(봇, 내 컴퓨터 안에서 측정) 기준 200명이 꽉 차 있을 때 서버가 내보내는 양은 약 15Mbps, CPU는 13% 정도예요. 집 와이파이로 직접 열 경우엔 업로드 속도가 이보다 넉넉해야 해요.

한 사람이 탭이나 봇을 잔뜩 열어 정원을 채우지 못하게 **같은 IP에서는 10개 연결까지만** 받아요(웨이팅 포함, `MAX_PER_IP`로 바꿔요). 넘으면 "같은 곳에서 너무 많이 접속했어요" 안내가 뜨고 15초마다 다시 시도해요. 통신사 폰은 여러 명이 IP 하나를 같이 쓰기도 해서 넉넉하게 잡았어요. 내 컴퓨터(localhost)에서 테스트할 땐 제한이 없어요. 제한을 직접 보려면 미리보기 설정 `festival-ip-test`(3003, 한도 2)를 켜고 `http://<내 컴퓨터 IP>:3003`을 탭 3개로 열어요.

## 배포 (Fly.io 도쿄)

[fly.toml](fly.toml)과 [Dockerfile](Dockerfile)이 준비돼 있어요. 접속자·웨이팅·NPC 상태를 서버 메모리에 들고 있어서 **서버는 꼭 1대만** 돌려요. 아무도 없어도 꺼지지 않게 해 두었어요.

처음 한 번:

```bash
brew install flyctl
```

```bash
fly auth login
```

```bash
fly apps create teum-rock-fest
```

이름이 이미 쓰이고 있으면 다른 이름으로 만들고 `fly.toml`의 `app`도 같이 바꿔요. 그다음 배포해요:

```bash
fly deploy --ha=false
```

`--ha=false`를 빼면 서버가 2대 만들어져서 사람들이 서로 안 보이는 두 축제로 나뉘어요. 실수로 2대가 됐으면 `fly scale count 1`로 줄여요. 주소는 `https://<앱 이름>.fly.dev`예요.

- **전광판·광고 바꾸기**: `billboard.json`이나 `public/ads/`를 고친 뒤 `fly deploy`를 다시 해요. 배포하는 동안 접속자는 잠깐 끊겼다가 원래 자리로 다시 붙고, 웨이팅 번호는 처음부터 다시 매겨져요.
- **로그·상태**: `fly logs`, `fly status`
- **서버 크기**: 지금은 `shared-cpu-1x`, 메모리 512MB예요. 사람이 많아져서 끊김이 생기면 `fly.toml`의 `[[vm]]`을 `shared-cpu-2x`나 `performance-1x`로 올려요.
- **트래픽 비용**: 꽉 차면 서버가 시간당 약 6.7GB를 내보내요. Fly 대시보드에서 송신량과 요금을 가끔 확인해요.

## 검색 노출 (SEO·GEO)

"틈락페"는 처음 보는 단어라서, **락페·락페스티벌·록페스티벌·부락페** 같은 이미 많이 찾는 말과 함께 검색되도록 해 두었어요.

- `public/index.html`: 제목·설명에 락페/부락페 키워드, 대표 주소(canonical), OG·트위터 카드, 구조화 데이터(JSON-LD: `WebSite` + `VideoGame`). 게임 화면은 캔버스라 글이 없어서 입장 카드 아래 `/about` 링크를 걸어 검색엔진이 따라가게 했어요. `game.js`는 `<title>`을 덮어쓰지 않아요.
- `public/about.html` → `/about`: 소개·즐기는 법·락페 용어·FAQ를 글로 담은 페이지. 검색엔진과 AI 답변(GEO)이 실제로 읽는 곳이에요. FAQ는 본문과 JSON-LD(`FAQPage`) 문구를 똑같이 맞춰요 (하나를 고치면 다른 쪽도 고쳐요). 부락페와는 관계없는 독립 프로젝트라고 분명히 적어 두었어요.
- `public/robots.txt`, `public/sitemap.xml`: 모든 크롤러 허용(`/music/`만 제외), 사이트맵 위치 안내. 페이지를 고치면 `sitemap.xml`의 `lastmod`와 `about.html`의 수정일도 바꿔요.
- `public/llms.txt`: AI 검색·챗봇이 틈락페를 요약할 때 쓰는 한 장짜리 설명.
- 아이콘: `favicon.svg`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png`, `site.webmanifest` (`/favicon.ico`는 `icon-192.png`를 줘요).
- 서버: `/about.html`·`/index.html`로 오면 `/about`·`/`로 301 이동해서 주소가 하나만 색인돼요.

배포한 뒤 한 번 직접 해야 하는 일:

1. [네이버 서치어드바이저](https://searchadvisor.naver.com)에 사이트를 등록해요. 소유 확인은 HTML 태그 방식으로 받은 `<meta name="naver-site-verification" ...>`를 `index.html`의 `<head>`에 넣고 다시 배포해요. 그다음 사이트맵(`https://teum-rock-fest.fly.dev/sitemap.xml`) 제출, 웹 페이지 수집 요청(`/`, `/about`)을 해요.
2. [구글 서치 콘솔](https://search.google.com/search-console)도 같은 방식(`google-site-verification` 메타 태그)으로 확인하고 사이트맵을 제출해요.
3. [다음 검색등록](https://register.search.daum.net/index.daum)에 사이트를 등록해요.
4. 인스타그램·블로그·커뮤니티에 `https://teum-rock-fest.fly.dev/` 링크를 "온라인 락페", "부락페" 같은 말과 함께 올리면 검색 순위에 가장 크게 도움이 돼요. 나중에 자기 도메인을 쓰게 되면 canonical·OG·sitemap·robots·llms.txt·JSON-LD의 주소를 한꺼번에 바꿔요.

## 방문 통계 (파이어베이스 애널리틱스)

`public/stats.js`가 파이어베이스 애널리틱스(GA4)를 불러와요. 게임(`/`)과 소개 페이지(`/about`) 둘 다 방문(`page_view`)은 자동으로 세요.

- 지금 연결된 곳: Firebase 프로젝트 `teumrockfestival` (측정 ID `G-HDDWCFMD1J`).
- 켜는 법 (프로젝트를 바꿀 때): [파이어베이스 콘솔](https://console.firebase.google.com)에서 프로젝트를 만들고(애널리틱스 사용 켜기) 웹 앱을 추가한 뒤, 나오는 `firebaseConfig`를 `stats.js`의 `FIREBASE_CONFIG`에 넣고 다시 배포해요. 비워 두면(`null`) 아무것도 안 보내요. 웹 설정값은 공개돼도 괜찮은 값이에요.
- 내 컴퓨터(localhost)에서는 안 보내요. 확인하고 싶으면 주소에 `?ga`를 붙여요. 이벤트가 오는지는 콘솔 > 애널리틱스 > 실시간(또는 DebugView)에서 봐요.
- 게임 이벤트 (`game.js`의 `track`). 이름·팔찌 번호 같은 개인 정보는 안 보내요.

  | 이벤트 | 언제 | 값 |
  | --- | --- | --- |
  | `tutorial_begin` | 이름을 적고 다음으로 | |
  | `band_issued` | 팔찌 착용 | `visits` (며칠째) |
  | `tutorial_complete` | 캐릭터 고르고 입장 버튼 | |
  | `join_festival` | 서버에 들어옴 (다시 연결될 땐 안 셈) | `kind` (new·returning·daily·queue), `visits`, `online`, `touch` |
  | `mat` | 돗자리 | `act` (open·move·fold) |
  | `action` | 동작을 켬 | `name` (hands_up·rhythm·slam·flag) |
  | `customize` | 꾸미기 저장 | |
  | `queue_wait` | 정원이 차서 웨이팅 시작 | `ahead`, `cap` |

- 광고 차단기가 막아도 게임은 그대로 돌아가요 (`track`은 없으면 그냥 넘어가요).

## 구조

- `server.js`: 정적 파일과 WebSocket 서버. 초당 10번, 움직이거나 동작이 바뀐 사람만 골라서 압축해 보내요 (이름·외형·돗자리는 바뀔 때만)
- `public/shared.js`: 서버와 클라이언트가 같이 쓰는 맵 배치, 구역 규칙, NPC 관객 (고정 시드라 모두에게 똑같이 보여요)
- `public/about.html`: 검색엔진·AI용 소개 페이지 (`/about`)
- `public/stats.js`: 파이어베이스 애널리틱스 (방문 통계·게임 이벤트)
- `public/game.js`: 픽셀 렌더링, 입력, 낮/노을/밤/새벽 (한국 시간 기준, 서울의 계절별 해 뜨고 지는 시각에 맞춤)

테스트할 때는 `?t=0.47`(노을), `?t=0.7`(밤)처럼 주소 뒤에 붙이면 시간대를 고정할 수 있어요.
